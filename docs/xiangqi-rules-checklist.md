# 标准象棋规则与合法局面 Checklist

> **文档性质**：给工程师的修复规格 + 给 QA 的验收基准。
> **背景**：现有训练 App 的练习题库出现「自己一方 3 个车」「老将在不合适位置」等非法局面。根因是题库只校验了解法着法是否合法，未校验**局面本身**是否合法（见 §7）。
> **适用范围**：中国象棋标准规则（红先、无敌方特殊规则），用于局面校验器、题库导入、残局编辑、单元测试。
> **优先级**：**P0 = 必做（不通过则局面判非法，禁止入题库）**；**P1 = 应做（强烈建议，首版可随 P0 一起落地）**；**P2 = 可选增强**。

## 0. 前置约定：本项目坐标与局面格式

| 项目 | 约定 |
|---|---|
| 棋盘 | 9 列 × 10 行；`col` 0..8（从左到右），`row` 0..9 |
| 方向 | `row 0` = 红方底线，`row 9` = 黑方底线；红方向 `row +1` 前进，黑方向 `row -1` 前进 |
| 红方九宫 | `col ∈ [3,5]` 且 `row ∈ [0,2]` |
| 黑方九宫 | `col ∈ [3,5]` 且 `row ∈ [7,9]` |
| 河界 | `row 4` 与 `row 5` 之间；红方阵地 `row 0..4`，黑方阵地 `row 5..9` |
| 棋子代码 | `K` 将/帅、`A` 士/仕、`B` 象/相、`N` 马、`R` 车、`C` 炮、`P` 兵/卒 |
| 局面串 | 本项目 `Board.fromNotationSetup()` 格式：10 段用 `/` 分隔（row 0 → row 9），每段 9 个逗号分隔单元格；`.` = 空；**大写 = 红，小写 = 黑** |
| 表示例 | `R,N,B,A,K,A,B,N,R` = 红方底线 9 子 |

> 说明：以上与 `src/engine/types.ts`、`src/engine/movegen.ts`、`src/engine/pieces.ts` 现有实现完全一致，校验器应复用同一套常量，不要另起炉灶。

### 1.2 关键发现：成熟产品如何防止非法局面进入题库/对局

1. **把「局面合法性」当作独立关卡，而不是只校验着法。** Pikafish 在「编辑局面」完成时即校验，不合法则提示并阻止完成；在「导入棋谱」时同样拦截（S8）。这正是我们缺失的环节。
2. **校验项的最小集合高度一致**：① 双方将帅各恰好一枚且位置合规；② 将帅不得照面；③ 非走子方不得处于被将状态；④ 棋子不得越界/重叠（FEN 结构合法性，S9/S13）。
3. **着法合法性 = 几何合法 + 不留下己方被将。** 开源实现通过「模拟走子后枚举对方所有着法能否打到己方将帅」+「单独检测照面」来实现（S10/S11）。
4. **困毙判负**是象棋与国际象棋的关键差异，必须在终局判定中显式处理（S2/S6/S11）。

## B. 各棋子走法与限制（逐条可验证）

| 棋子 | 走法 | 关键限制 | 优先级 |
|---|---|---|---|
| **将/帅 K** | 九宫内沿横/竖线每次走 1 格 | ① 目标必须在己方九宫：红 `col 3..5, row 0..2`；黑 `col 3..5, row 7..9`。② **将帅不可照面**：双方将帅同列且中间无任何棋子时，形成该局面的一方判负/该着法非法（飞将）。 | P0 |
| **士/仕 A** | 九宫内沿斜线每次走 1 格 | 目标必须在己方九宫。合法落脚点仅 5 个：红 `(3,0)(5,0)(4,1)(3,2)(5,2)`；黑 `(3,7)(5,7)(4,8)(3,9)(5,9)`。 | 走法 P0；落脚点收敛 P1 |
| **象/相 B** | 沿对角线走 2 格（田字） | ① 不得过河：红 `row ≤ 4`，黑 `row ≥ 5`。② **塞象眼**：田字中心格有任意棋子（不论敌我）则不可走。③ 合法落脚点：红 `col∈{0,2,4,6,8} 且 row∈{0,2,4}`；黑 `col∈{0,2,4,6,8} 且 row∈{5,7,9}`。 | 不过河/象眼 P0；落脚点收敛 P1 |
| **马 N** | 先直（横）1 格再斜 1 格（日字） | **蹩马腿**：紧邻的直行/横行格（马腿）有任意棋子则不可走。 | P0 |
| **车 R** | 直线（横/竖）任意格数 | 不可越过任何棋子；遇己子停，遇敌子可吃并停。 | P0 |
| **炮 C** | 不吃子时同车 | **吃子必须隔恰好一个棋子（炮架，敌我均可）**；炮架之后遇到的第一个棋子若为敌方方可吃，为己方则不可吃。 | P0 |
| **兵/卒 P** | 未过河只可向前进 1 格；过河后可前进或左右各 1 格 | **任何情况下不可后退**。红兵 `row ≥ 5` 视为过河，黑卒 `row ≤ 4` 视为过河。位置下界：红兵不可能出现在 `row 0..2`，黑卒不可能出现在 `row 7..9`。 | 走法 P0；位置下界 P1 |

> 来源：S1、S2、S3、S6。项目实现 `src/engine/movegen.ts` 已覆盖上述几何规则；本 Checklist 的作用是**补齐局面层的校验**，而非重复实现走法。

## C. 合法局面判定规则（核心 · 用于修题库）

> 定义：函数 `validatePosition(board, turn) → { valid: boolean, errors: string[] }`。
> 一个局面**必须同时满足下列全部 P0 约束**才算合法；任何一条不满足，**禁止进入题库/对局/AI 搜索**并返回明确错误原因。

### C.1 P0（必做）

| # | 约束 | 判定方法 | 拦截的问题 |
|---|---|---|---|
| **C1** | **棋盘结构合法**：恰好 9×10 格；每枚棋子 `col∈[0,8]、row∈[0,9]`；每格至多 1 枚棋子 | 解析时逐格计数；越界/重叠直接报错；拒绝静默忽略非法 token 或不足 9 格的行 | 越界棋子、格式错乱局面 |
| **C2** | **每方将/帅恰好 1 枚**：红 K 计数 == 1，黑 k 计数 == 1 | 全盘扫描 K/k 分别计数 | 缺将、多将 |
| **C3** | **将/帅必须在己方九宫内**：红 `col 3..5 且 row 0..2`；黑 `col 3..5 且 row 7..9` | 对 C2 找到的每枚 K/k 检查区域 | 「老将在不合适位置」 |
| **C4** | **各兵种数量不超过初始上限**（每方独立）：`K≤1（且==1）、A≤2、B≤2、N≤2、R≤2、C≤2、P≤5` | 按 side+type 分组计数，与上限比较 | **「自己一方 3 个车」** |
| **C5** | **将帅不可照面**：两将同列且中间（两者 row 之间）无任何棋子 → 非法 | 取两将坐标；若同 col，逐格检查中间是否为空 | 飞将局面 |
| **C6** | **非走子方不得被将军**：`turn` 为轮到走子的一方；**另一方**（刚走完棋的一方）的将/帅不得处于被攻击状态 | 设 `nonMover = opponent(turn)`，调用现有 `isInCheck(board, nonMover)`（已含照面判定）为 true 则非法 | 不可能由合法着法到达的局面 |

**C6 说明（极易写反，务必注意）**：轮到红走（`turn='red'`）时，被将军的可以是黑（红刚将军，黑必须应将）；此时**必须保证红方自己没有被将军**。换言之，被检查的是"上一手走子方"。若写反，会把大量正常的将军局面误判为非法。

**附加（P0，实现层）**：`isInCheck()` 目前在"找不到将帅"时返回 `false`，因此 **C2 不能依赖 `isInCheck` 兜底**，必须先独立执行 C2。

### C.2 P1（应做）

| # | 约束 | 判定方法 |
|---|---|---|
| **C7** | 士/仕只能位于 §B 列出的 5 个九宫斜线点之一 | 逐枚检查 side+type+坐标白名单 |
| **C8** | 象/相不得过河，且只能位于 §B 列出的田字落脚点 | 红 `row ≤ 4`、黑 `row ≥ 5`，且 col 为偶数、row 与初始 parity 一致 |
| **C9** | 兵/卒位置下界：红兵 `row ≥ 3`、黑卒 `row ≤ 6` | 逐枚检查象棋不可倒退推出的可达范围 |
| **C10** | 总子数 ≤ 32，每方 ≤ 16 | 可由 C4 推导，作为快速前置过滤 |
| **C11** | 解析严格性：未知棋子字符、错误维数、重复定义同一格必须报错，不得静默跳过 | 修改 `fromNotationSetup` / `fromSetup` 增加严格模式 |

### C.3 建议的接入点（修复范围）

1. `src/data/puzzles.ts` 的 `validatePuzzle()` —— 在回放解法前先调用 `validatePosition(p.setup, turn)`；当前它**只验证解法着法**，这是题库出现非法局面的直接原因。
2. `Board.fromNotationSetup()` / `Board.fromSetup()` —— 提供 `strict` 选项；题库导入、棋谱导入路径必须开启。
3. 题库/残局编辑保存入口与任何 FEN/setup 导入入口 —— 保存前强制校验，失败则拒绝并提示具体违反的条款号。
4. `src/ai/search.ts` 根节点 —— 防止把非法局面喂给 AI（P1）。
5. QA 测试 —— 将 §E 用例固化为回归测试。

## D. 胜负 / 终局判定

| 状态 | 定义 | 判定要点 | 优先级 |
|---|---|---|---|
| **将军 check** | 一方棋子攻击对方将/帅，下一着可吃掉 | 轮到被将方时，必须应将 | P0 |
| **将死 checkmate** | 被将军方**无任何合法着法**化解 | `isInCheck(board, turn) == true` 且 `generateLegalMoves(board, turn).length == 0` → 被将方负 | P0 |
| **困毙 stalemate** | 轮到走子的一方**未被将军但无任何合法着法** | **象棋判负（与国际象棋判和相反）**；项目 `GameStatus='stalemate'` 必须在 UI/计分上按"负"处理 | P0 |
| **自杀（非法着法）** | 走后形成将帅照面、主动送将、或被将时未应将 | 由 `isLegalMove` 拦截；不得允许该着法产生 | P0 |
| **和棋 draw** | ① 双方均无取胜可能的简单局面；② 60 回合内双方均未吃子（自然限着）；③ 三次重复且符合不变作和；④ 一方提和另一方同意 | 当前引擎 `draw` 仅为占位，未实现；对训练 App 建议至少实现「无子可动≠和棋」的认知，重复/自然限着列为 P1/P2 | P1 |

来源：S2、S6、S7、S11。项目 `src/engine/rules.ts:checkStatus()` 已正确区分 checkmate / stalemate / check / playing，但**未实现 draw 的判定**，需在 UI 层明确"困毙=负"。

## 8. 给工程师的落地要点（优先级排序）

1. **新增独立的局面校验层**（`validatePosition`），而不是继续在走法层打补丁。走法层（`movegen.ts`/`rules.ts`）本身是正确的，问题在于**入口没有校验局面**。`validatePuzzle()` 目前只回放解法，这是根因。
2. **C6 的方向别写反**：检查的是"非走子方"，用 §E.2/P2 与 §E.1/N6 同一 setup 不同 turn 的对照测试锁死。
3. **C2/C3/C4 必须是纯计数与区域检查**，不要依赖 `isInCheck()`（缺将时它返回 false，会漏判）。
4. **题库数据要一起修**：见 §7；只加校验器而不修数据，会导致现有 5 个残局全部被拒、练习内容变空。
5. **解析严格化**（P1）：`fromNotationSetup` 目前会静默忽略未知字符与格式错误，建议题库导入路径开启严格模式并回报具体错误位置。
