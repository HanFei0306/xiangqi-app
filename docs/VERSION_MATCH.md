# 版本对弈自测机制（v2026.11.19.8 起默认附带）

目标：**每一个新版本的 AI 都必须用实际对局证明不弱于上一版本**，不能只看搜索深度或节点吞吐。

## 1. 基线快照

- 当前基线：`src/ai/legacy/v1197/`，是 v2026.11.19.7 引擎的显式源码快照（v19.8/v19.9  AI 均以它为对手完成对弈门禁）。
- 一键门禁：`npm run release-check` = typecheck + 全量测试 + 三层版本对弈，任何一步失败都不得出包。
- 基线只依赖 `src/engine/*` 的公共规则层，使用独立的学习 stub，因此可重复、不读写 localStorage。
- 下一次迭代（v19.9）开始前，必须先把当时的 `src/ai/*.ts` 复制成新的 `src/ai/legacy/v1198/`，并调整相对导入；新探针改为加载新基线。
- 快照要保留旧版的已知缺陷（例如 v1197 保留了困毙判和、被将硬截断），否则对弈基线会被无意抬高，失去意义。

## 2. 三层验证

| 层级 | 命令 | 用途 | 通过标准 |
|---|---|---|---|
| 限时实战 | `npm run version-match` | 300ms/步，4 局，先后手轮换，固定种子 | 新版胜局 ≥ 旧版胜局 |
| 深时限实战 | `npm run version-match:deep` | 800ms/步，4 局 | 新版胜局 ≥ 旧版胜局 |
| 同深度隔离 | `npm run version-match:fixed` | 固定 depth=4、无预算、无开局库、无杀棋证明、无变着 | 新版胜局 ≥ 旧版胜局 |
| SPRT 显著性 | `npm run sprt` | 12 局、120ms/步、elo0=0 / elo1=200，记录漏杀与臭招样本 | 新版胜局 > 旧版且 LLR ≥ ln20≈2.996 |

固定深度层隔离了时间噪声，是搜索/评估质量的直接证据；限时层验证真实产品路径（含开局库、杀棋证明、变着）。

## 3. 对局规则

- 规则层与棋盘完全共用，只有引擎实现不同。
- `setGameSalt()` 固定每局 salt；先后手交替；最多 140 回合。
- 将死或困毙：行棋方负；三次重复：和棋；回合上限时用 `full` 评估判断优势。
- 输出 JSON：胜/负/和、回合数、终局原因、最终红方评估。

## 4. 迭代门禁（每次棋力相关改动都必须执行）

1. 先备份核心 AI 文件到 `_backup/`。
2. 修改前后都跑 `npm test` 与 `npm run typecheck`。
3. 跑 `npm run release-check`（= typecheck + 全测 + 三层对弈 + SPRT）。任何一层新版胜局少于旧版，或 SPRT 未显著胜出 → 回退该项改动，不允许用“深度更高”替代。
4. `probe-sprt-v1200.mts` 同时输出漏杀（`missed-mate`）和 >300cp 臭招（`blunder`）样本及 setup，作为后续调参/训练样本；v19.8 后新增的杀棋证明使漏杀样本为 0。
4. v19.8 实际教训：
   - LMP 延迟着法剪枝与 SEE 静态交换剪枝让限时对弈从 4:0 变成 0:4，已回退；
   - `selectAmongPeers` 的 ±10cp/±50cp 容差会在短预算噪声下把“接近最好”的着法当成等价着法换掉，收紧到完全同分后 300ms 四局 4:0。
5. 外部“天天象棋大师水准”无法在本机自动化验证，必须在发布说明里标注为待用户实测，并附人工对局清单。

## 4.1 非棋力改动也要回归

音效/布局等改动不改变 AI，但每次出包仍执行 `release-check`，确保没有连带把棋力改坏。  
v19.9 残局音效真机无声的根因是“setTimeout 到点再创建 AudioNode”被 Android WebView 丢弃；已改为手势内 `playAt()` + Web Audio 时钟预约，CDP 实测点击后 5 个节点全部起振。

## 4.2 本环境的工程边界（诚实说明）

- Pikafish/NNUE：本机没有可合法随 APK 分发的轻量训练网络与训练样本，且 `file://` WebView 不允许外部权重文件 fetch。当前采用公开象眼 PST + 手工动态项；NNUE 属于需要单独数据集与训练流水线的后续阶段，不在本版假装完成。
- Lazy SMP 多线程：Android WebView 的 `file://` 环境禁用了 Worker URL，无法安全起多线程；当前用每根着分片 + 帧让出实现协作式时间分片，单线程不卡顿。
- Bitboard：现有合法着法生成基于 32 活跃子槽位与缓存攻击检测，已经是 O(32) 而非 90 格全扫；完整位棋盘重写收益不足以抵消回归风险，未在本版冒险。
- SEE 剪枝：v19.8 实证对弈有害已回退，但 SEE 仍用于吃子排序（零剪枝风险）。

## 5. 产物命名

- 版本号：`vYYYY.MM.DD.N`，UI 三处徽标、AndroidManifest `versionName`、打包脚本打印串必须一致。
- APK 文件名：`xiangqi-vYYYY.MM.DD.N.apk`，由 `build_final.py` 从 Manifest 自动读取生成。
